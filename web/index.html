📖 深度解读 · 写作规范

按青稞社区（qingke-tech-writing）风格执行，每次生成与审校都遵守以下规则：

  • 导语：开头 3 段内讲清「论文回答什么问题 → 为什么现在值得读 → 作者给出什么」。
  • 结构：小节标题用结论句/名词短语，禁「引言 / 相关工作 / 背景介绍」腔与编号模板；每节先给加粗结论再展开。
  • 篇幅：正文目标 3000–6000 字；低于 2500 字视为未达标。
  • 术语：Agent / RL / SFT / RLHF / World Model / benchmark 等保留英文；方法/模型/机构名一律原文。
  • 数字：规模 / 数据集 / 设置 / 基线 / 单位齐全；论文声称与「我们的判断」分开。
  • 图片：正文至少分散嵌 3 张关键图，（图N）引用写在讲对应内容的段落里。
  • 出处：文首自动生成出处块——作者 / 机构 / 时间 / Paper / arXiv / Code。
  • 收尾：给一句具体的社区视角判断，不升华成金句。
  • 反 AI 味：禁「随着…的发展」「首先/其次/最后」「总而言之」等模板腔。
  • 全文理解：结构化切片 + 研究地图 + 按小节检索证据，不只看前半篇。
  • 证据审计：成稿后核对数字 / 模型与数据集名 / 消融 / 局限 / 公式 / 图；只重写有问题的小节。

规则来源：qingkelab/agent-skills · qingke-tech-writing

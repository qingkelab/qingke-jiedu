    📖 深度解读 · 写作规范

    按青稞社区（qingke-tech-writing）风格执行，每次生成与审校都遵守以下规则：

    • 导语：开头 3 段内讲清「论文回答什么问题 → 为什么现在值得读 → 作者给出什么」。
    • 结构：小节标题用结论句/名词短语，禁「引言 / 相关工作 / 背景介绍」腔与编号模板；每节先给加粗结论再展开（一段至多一个加粗点）。
    • 篇幅：正文目标 3000–6000 字（不含出处块/图片/公式）；低于 2500 字视为未达标，靠加深机制细节与证据解读扩写，不注水。
    • 术语：Agent / Harness / Policy / RL / SFT / RLHF / Skill / World Model / benchmark 等社区通用词保留英文、不硬译；方法/模型/机构名一律原文；新概念首次出现定形后全文只用一种形态。
    • 数字：模型规模 / 数据集 / 设置 / 对比基线 / 单位齐全；口径精确（「提升至 X」是终值、「提升了 X」是增量，百分比写清基数）；论文声称与「我们的判断」分开。
    • 图片：正文至少分散嵌 3 张关键图，（图N）引用写在讲对应内容的段落里（架构图放讲架构处、结果图放讲结果处、公式图放讲公式处）；禁止在文末集中写「（图1）…（图2）…」式图注清单；每张图自动补一行引用式图注。
    • 出处：文首自动生成出处块——作者 / 机构 / 时间 / Paper / arXiv / Code；正文不再重复链接块。
    • 收尾：给一句具体的社区视角判断（与既有工作的关系、可复现性、最该补的验证），不升华成金句。
    • 反 AI 味：禁「随着…的发展」「首先/其次/最后」「总而言之」「不是 A 而是 B」「本质上 / 更重要的是」等模板腔与空泛开头。
    • 审校：生成后自动对照原文自检一遍（出处 / 导语 / 结构 / 术语一致 / 数字口径 / 图片引用 / 去 AI 味）。
    • 全文理解：先做结构化切片（章节 / 段落 / 公式 / 图注 / 表格）与「研究地图」（问题 / 主张 / 方法 / 结果 / 消融 / 局限 + 证据定位），逐节写作按小节从全文检索证据，不再只看前半篇。
    • 证据审计：成稿后核对数字 / 模型与数据集名 / 消融 / 局限 / 公式 / 图与正文对应；发现问题只重写有问题的那一节。
